# Library API

A REST API developed with .NET to study and apply the SOLID principles in a practical backend application.

This project is part of my studies on software architecture, clean code, object-oriented programming, and best practices for building maintainable and scalable APIs.

## Objective

The main goal of this project is to understand how SOLID principles can be applied to real-world backend development.

The project is being developed incrementally as I study different concepts related to software design and architecture.

## SOLID Principles

### Single Responsibility Principle (SRP)

A class should have only one reason to change and should be responsible for a single part of the application's functionality.

### Open/Closed Principle (OCP)

Software entities should be open for extension but closed for modification.

### Liskov Substitution Principle (LSP)

Objects of a derived type should be replaceable with objects of their base type without affecting the correctness of the application.

### Interface Segregation Principle (ISP)

Classes should not be forced to depend on interfaces they do not use.

### Dependency Inversion Principle (DIP)

High-level modules should not depend directly on low-level modules. Both should depend on abstractions.
